## 1. What is Docker?
Docker is an open-source platform used to **build, package, and run applications in containers**. Containers bundle an application with all its dependencies (libraries, binaries, config files) so it runs consistently across any environment — from a developer's laptop to production servers.

## 2. Why Docker? (Problem It Solves)
- Eliminates the "it works on my machine" problem.
- Provides lightweight, fast, and portable application environments compared to traditional Virtual Machines.
- Enables consistent environments across development, testing, and production.
- Simplifies dependency management by packaging everything the app needs inside the container.
- Makes scaling and deployment faster and more predictable.

## 3. Containers vs Virtual Machines
| Feature | Containers | Virtual Machines |
|---|---|---|
| OS | Share host OS kernel | Each has its own full OS |
| Size | Lightweight (MBs) | Heavy (GBs) |
| Startup Time | Seconds | Minutes |
| Isolation | Process-level | Full hardware-level |
| Performance | Near-native | Overhead due to hypervisor |
| Portability | Highly portable | Less portable |

## 4. Core Docker Concepts
- **Image** — A read-only template containing the application code, runtime, libraries, and dependencies. Images are built using a `Dockerfile`.
- **Container** — A running instance of an image. Lightweight and isolated from other containers.
- **Dockerfile** — A text file with instructions to build a Docker image (e.g., `FROM`, `COPY`, `RUN`, `CMD`).
- **Docker Hub** — A public/private registry to store and share Docker images.
- **Volume** — A mechanism to persist data generated by containers, independent of the container lifecycle.
- **Network** — Allows containers to communicate with each other and the outside world.
- **Layer** — Each instruction in a Dockerfile creates a cached layer, making rebuilds faster.

## 5. Basic Dockerfile Example
```dockerfile
# Use an official base image
FROM node:18-alpine

# Set working directory
WORKDIR /app

# Copy dependency files and install
COPY package*.json ./
RUN npm install

# Copy application code
COPY . .

# Expose port
EXPOSE 3000

# Command to run the app
CMD ["node", "server.js"]
```

## 6. Essential Docker Commands
```bash
# Build an image from a Dockerfile
docker build -t myapp:1.0 .

# Run a container from an image
docker run -d -p 3000:3000 --name myapp-container myapp:1.0

# List running containers
docker ps

# List all containers (including stopped)
docker ps -a

# Stop a running container
docker stop myapp-container

# Remove a container
docker rm myapp-container

# List images
docker images

# Remove an image
docker rmi myapp:1.0

# View container logs
docker logs myapp-container

# Access a running container's shell
docker exec -it myapp-container /bin/sh

# Pull an image from Docker Hub
docker pull nginx

# Push an image to a registry
docker push myrepo/myapp:1.0
```

## 7. Docker Compose
Docker Compose is used to define and run **multi-container applications** using a single YAML file (`docker-compose.yml`).

```yaml
version: '3.8'
services:
  web:
    build: .
    ports:
      - "3000:3000"
  database:
    image: mongo
    ports:
      - "27017:27017"
    volumes:
      - db-data:/data/db
volumes:
  db-data:
```

Run it with:
```bash
docker-compose up -d
```

Stop it with:
```bash
docker-compose down
```

## 8. Docker Architecture
- **Docker Client** — CLI/UI the user interacts with to issue commands.
- **Docker Daemon (dockerd)** — Background service that manages images, containers, networks, and volumes.
- **Docker Registry** — Stores Docker images (e.g., Docker Hub, AWS ECR, Google Container Registry).

```
Client  --commands-->  Docker Daemon  --pulls/pushes-->  Registry
                            |
                      Manages Images, Containers,
                      Networks & Volumes
```
